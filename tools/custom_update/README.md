# 個人フォークの更新

この仕組みは個人フォークの更新用です。本家へPR・Issue・コメント・pushを行いません。本家の最新の安定版だけを読み取り、プレリリースは自動導入しません。

## 動作

Windowsのタスクスケジューラから `run.ps1 -ConfigPath <PC内の設定ファイル>` を実行します。GitHubに自己ホストランナーや署名鍵は登録しません。PCの起動と、設定したWindowsユーザーのサインインが必要です。Codexアプリの起動は不要です。

1. 自分のフォークのmainと本家の最新安定版を取得します。
2. 未取り込みの安定版だけを専用作業コピーへマージします。競合時は中断します。
3. カスタム用バージョン番号を増やし、テストと公開用ビルドを行います。
4. 同じ署名鍵で署名し、署名・配置・パッケージ・プライバシーを検査します。
5. 自分のフォークへソースとAPKを公開し、APKを再ダウンロードしてハッシュを照合します。
6. 最後に `custom-update.json` を切り替えます。テレビでは更新内容を確認してインストールします。

更新がなければビルド・配布は行いません。取得失敗・競合・テスト失敗・秘密情報の検出時は公開を止めます。既存のテレビのインストールには触りません。

## 公開範囲

公開するのはソース、署名済みAPK、一般的な更新説明、APKのハッシュ・サイズ・バージョンだけです。接続先URL、APIトークン、署名秘密鍵、PC内のパス、詳細ログ、テスト用音声、テレビ画面は公開しません。公開APKにはGitHubの公開アカウント名を含む既存の署名証明書が含まれます。実名や実メールアドレスを追加することはありません。

`-PpublicRelease` は個人用のAI初期値を無効にします。初回の移行前に既存のAI設定画面で「保存」し、接続先を端末内に永続化してください。

設定ファイルにはSDK・Java・Git・gh・Python・PowerShell・フォントの場所、署名鍵とDPAPI保護したパスワードファイルの場所、継続用証明書のSHA-256、公開してはいけない値、任意の宅内結合テスト用環境変数を指定します。設定ファイルはPC内にだけ置き、リポジトリへ追加しません。

## 手動操作と復旧

- 検知のみ: `run.ps1 -ConfigPath <設定> -CheckOnly`
- カスタム修正後の配布: `run.ps1 -ConfigPath <設定> -Force`
- 結果: 設定ファイルと同じフォルダーの `status.json`
- 詳細: 同じフォルダーの `logs/`。外部へそのまま貼り付けないでください。
- 一時停止: タスクスケジューラの「Komorebi Custom Update」を無効化します。

署名鍵と復旧に必要な情報は別の安全な場所にも保管してください。DPAPIで保護したパスワードは元のWindowsユーザーに依存するため、ファイルを別PCへコピーするだけでは復旧できません。

自動取り込みが止まった場合は差分を確認して修正し、テスト後に個人フォークのmainへ反映します。本家へ自動で問い合わせません。`pending.json` がある場合は、次回実行時に公開済みAPKの同一性を確認して配布処理を再開します。既存リリースのAPKを上書きすることはありません。

## テスト

`python -m unittest discover -s tools/custom_update -p test_*.py`

Android側の更新情報検証・破損APK拒否のテストは `:app:testDebugUnitTest` に含まれます。
